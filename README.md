## التشغيل على جهازك
> ملحوظة: تم تحديث السن إلى قائمة منسدلة 18–80 حسب ملف DB الجديد (نوع العمود INTEGER كما هو، لا حاجة لتعديل الجداول).

1. ثبّت Node 18+ و PostgreSQL.
2. أنشئ قاعدة البيانات:  `createdb -U postgres wefaq`   (أو من pgAdmin)
3. انسخ `.env.example` إلى `.env` وعدّل كلمة سر postgres و`WA_NUMBER` و`ADMIN_KEY` و`JWT_SECRET`.
4. `npm install`
5. `npm run db:init`   ← ينشئ الجداول من ملف `spec.js` (يمكنك رؤية الـ SQL بـ `node db/init.js --print`)
6. `npm start` ثم افتح http://localhost:3000  (ومن الموبايل على نفس الشبكة: http://IP-جهازك:3000)
7. أنشئ حساب الأدمن (مرة واحدة): `npm run admin:create` ثم ادخل http://localhost:3000/admin.html بنفس البيانات.

## تحديث مهم عند الترقية من نسخة سابقة
شغّل `npm install` (مكتبة nodemailer الجديدة) ثم `npm run db:init` مرة تانية: بيضيف الجداول الجديدة (favorites, intro_requests) وعمود claimed_at من غير ما يمسح بياناتك. وأعد تشغيل السيرفر بعد أي تعديل في `.env`. ثم `npm run admin:create` لإنشاء حساب الأدمن (مفتاح ADMIN_KEY القديم لم يعد مستخدماً).

## الفلو

← المستخدم يبعت الرسالة ← الأدمن يطابق رقم المُرسل مع الرقم المسجل ويضغط "تفعيل" ← الحساب يتفعل تلقائياً عند المستخدم.

## إنتاج APK / AAB لجوجل بلاي (Capacitor – وليس Flutter)
المشروع ويب (Node + HTML/JS) فلا يُبنى بأمر `flutter`. نغلّف نفس الواجهة بـ Capacitor:
1. ثبّت Android Studio (يأتي معه Android SDK وJDK).
2. من مجلد المشروع:  `npm i @capacitor/core @capacitor/android` ثم `npm i -D @capacitor/cli`
3. عدّل `public/config.js` ليشير لعنوان السيرفر (للاختبار: `http://IP-جهازك:3000`، وللنشر: عنوان HTTPS).
4. `npx cap add android` (مرة واحدة) ثم `npx cap sync android` بعد أي تعديل في `public/`.
5. `npx cap open android` ثم من Android Studio: Build ← Build APK(s) للتجربة، أو Build ← Generate Signed Bundle (AAB) لجوجل بلاي.

> ملحوظة Android: للتجربة على سيرفر HTTP محلي يجب أن يكون `androidScheme` في `capacitor.config.json` هو `http` (وإلا يمنع الـ WebView الاتصال المختلط). عند النشر بسيرفر HTTPS غيّره إلى `https`.

### أوامر Android المختصرة (شغّلها من جذر المشروع، وليس من مجلد public)
`npm run android:add` (مرة واحدة) ← `npm run android:sync` (بعد أي تعديل) ← `npm run android:open`

## نشر مجاني بدون بطاقة ائتمان (Neon + Vercel)
قاعدة البيانات على **Neon** (Postgres مجاني دائم) والسيرفر على **Vercel** (Serverless، دائم التشغيل، بدون بطاقة). Render أصبح يطلب بطاقة فلم نعد نستخدمه.
1. **Neon:** سجّل في neon.com ← New Project ← انسخ Connection string (يبدأ بـ postgresql://، ويفضّل النسخة pooled).
2. **الجداول والأدمن على القاعدة السحابية (من جهازك):** ضع الرابط في `.env` كـ `DATABASE_URL` ثم `npm run db:init` ثم `npm run admin:create`.
3. **Vercel بدون GitHub:**
   `npm i -g vercel` ← `vercel login` ← `vercel` (أجب: Set up and deploy؟ Y، اسم المشروع wefaq، المجلد ./ ، لا تعدّل الإعدادات).
   ثم أضف المتغيرات: `vercel env add DATABASE_URL production` و`vercel env add JWT_SECRET production` (نص عشوائي طويل) و`vercel env add WA_NUMBER production`.
   ثم النشر النهائي: `vercel --prod` ← تحصل على رابط `https://wefaq-xxxx.vercel.app`.
4. افتح الرابط للتجربة، والإدارة على `/admin.html`.
5. **التطبيق:** ضع الرابط في `public/config.js` ثم `npx cap sync android` وابنِ الـ APK.
> Vercel Hobby للاستخدام الشخصي/التجريبي (غير التجاري). عند الإطلاق الفعلي انقل لخطة مناسبة.

### بديل مجاني من جهازك (بدون استضافة): Tailscale Funnel
تثبيت Tailscale وتسجيل الدخول (مجاني) ثم `tailscale funnel 3000` يعطيك رابط HTTPS ثابتاً لسيرفرك المحلي (يعمل طالما الجهاز والسيرفر شغّالين).

**للتحديث:** انسخ الملفات، `npm install`، ثم `vercel --prod` (المخطط يتحدث تلقائياً). بعدها المستخدمون القدامى (خاصة العرائس) سيُطلب منهم استكمال بيانات الولي من «حسابي ← تعديل بياناتي».
